# 小龙虾语音助手 V2 需求文档

## 模块架构（6 个独立模块）

```
┌────────────────────────────────────────────────────────────┐
│                      应用总控 (状态机)                        │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ┌─────────┐   ┌─────────┐   ┌──────────┐   ┌─────────┐  │
│  │ 1. VAD  │──→│ 2. ASR  │──→│3.关键词+  │──→│ 4. LLM  │  │
│  │  模块   │   │  模块   │   │ 动作派发  │   │  对话   │  │
│  └─────────┘   └─────────┘   └──────────┘   └─────────┘  │
│       │                                          │         │
│       ▼                                          ▼         │
│  ┌──────────┐                             ┌──────────┐    │
│  │5. 播放控制│                             │ 6. 音效  │    │
│  │ (AEC+队列)│                             │   模块   │    │
│  └──────────┘                             └──────────┘    │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 各模块职责

| # | 模块 | 输入 | 输出 | 备注 |
|---|------|------|------|------|
| 1 | **VAD** | Mic原始流(经AEC) | `voice_start` / `voice_end` 事件 | 通用模块，不关心业务 |
| 2 | **ASR** | 由VAD驱动启停 | 实时文本(interim/final) | 当前用 Web Speech API，可替换 |
| 3 | **关键词+动作派发** | ASR文本流 | 命令事件(`wake`/`send`/`exit`等) | 当前文本匹配，未来换关键词模型 |
| 4 | **LLM对话** | 用户完整输入 | AI回复文本 → 送TTS入队 | 异步，不阻塞输入 |
| 5 | **播放控制** | TTS音频队列 + VAD状态 | 扬声器输出 + AEC参考信号 | VAD控制暂停/恢复 |
| 6 | **音效** | 状态变更事件 + listening心跳 | 提示音 | 独立音频通道，不走播放队列 |

## 状态定义

| 状态 | 含义 |
|------|------|
| **wake_listening** | 默认启动状态。VAD + ASR 短识别，等唤醒词。无唤醒词+静默 → 丢弃文本 |
| **listening** | 唤醒后。VAD + ASR 持续积累文本。"说完了" + 静默2s → 发送 |
| **thinking** | 异步处理中（与 listening 并行，不阻塞用户继续说话） |
| **playing** | 有音频播放（受 VAD 控制暂停/恢复） |

> `listening` + `thinking` + `playing` 可以**同时存在**。

## 双轨并行 + 播放智能控制

```
┌─────────────────────────────────────────────────────┐
│ 输入轨 (永远在跑)                                     │
│                                                     │
│ wake_listening ──唤醒词──→ listening ──"说完了"+静默2s──→ 发送 │
│       ↑                      ↑                       │
│       └── "结束结束" ←────────┘                       │
│                              │                       │
│                    (发送后不停，继续 listening)         │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ 处理轨 (异步，不阻塞输入轨)                            │
│                                                     │
│ 收到发送 → thinking → LLM回复 → TTS音频入队            │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ 播放轨 (VAD 智能控制)                                 │
│                                                     │
│ 队列有音频 → VAD检测用户在说话? → 是: 等待(不播)        │
│                                  → 否: 开始播放       │
│ 播放中 → VAD检测到人声? → 暂停                         │
│ 暂停中 → VAD静默了? → 继续播放                         │
└─────────────────────────────────────────────────────┘
```

## 核心规则

### 规则1：默认 wake_listening

- 应用启动 → 直接进入 `wake_listening`（获取麦克风权限后）
- 不需要用户点按钮才开始监听

### 规则2：发送条件 = "说完了" + 静默2s 同时满足

```
用户说: "今天天气怎么样说完了"
                              ↓ 检测到"说完了"关键词，标记 pending
                              ↓ 继续等 VAD 静默2s
                              ↓ 2s到了 → 发送 "今天天气怎么样"
                              ↓ 输入轨继续 listening，不停
```

如果关键词后用户又继续说话（VAD未静默）→ 不发送，追加到 buffer。

### 规则3：播放轨受 VAD 实时控制

| 事件 | 播放行为 |
|------|---------|
| 队列有音频 + 用户在说话 | 不播，等着 |
| 队列有音频 + 用户静默 | 开始播放 |
| 播放中 + VAD检测到人声 | 暂停播放 |
| 暂停中 + VAD静默 | 继续播放 |
| 用户说"结束结束" | 清空队列，停止播放 |

## 关键词+动作派发模块（模块3 详细）

```
ASR文本 ──→ KeywordDispatcher
              │
              ├─ 匹配 "开始/小龙虾"  → emit('wake')     → 状态机: wake→listening
              ├─ 匹配 "说完了/发送"   → emit('send')     → 标记pending，等VAD静默2s
              ├─ 匹配 "结束结束"      → emit('exit')     → 状态机: →wake_listening
              ├─ 匹配 "暂停"         → emit('pause')    → 播放暂停
              ├─ 匹配 "继续"         → emit('resume')   → 播放恢复
              ├─ 匹配 "再说一次"      → emit('replay')   → 重播
              └─ 未来: "搜一下X"      → emit('tool', X)  → 快速工具调用
```

设计为独立模块的好处：
- 当前实现：正则匹配 ASR 文本
- 未来替换：接入 keyword spotting 模型（如 Porcupine），两路并行，任一命中即触发
- 动作表可配置、可扩展

## 音效模块（模块6 详细）

| 触发 | 音效 | 描述 |
|------|------|------|
| 进入 wake_listening | ♪♪♪ 升调 | 880→1100→1320Hz，表示系统启动 |
| wake → listening | ♪♪ 双音 | 唤醒成功确认 |
| 触发发送 | ♪♪ 双音 | 收到指令确认 |
| 播放恢复 | ♪ 单音 | 轻提示 |
| 退出 listening | ♪♪♪ 降调 | 880→660→440Hz |
| **listening 心跳** | ♪ ... ♪ ... ♪ | 每3-5秒一个极轻单音（200Hz, 音量很低），告知用户"我在听" |

### listening 心跳音特点

- 仅在 `listening` 状态 + VAD 静默时播放
- 用户开口说话 → 立即停止心跳
- 音量极低（gain ~0.03），不干扰对话
- 走独立 OscillatorNode，**不进播放队列、不触发 AEC**
- 频率低（~200Hz），时间短（~80ms），间隔 3-5 秒

## 新增 UI 功能

### 设备显示

- 顶部显示当前麦克风名称 + 音频输出设备名称
- 使用 `navigator.mediaDevices.enumerateDevices()` 列出设备
- 可点击切换设备

### 日志面板

- 底部抽屉式弹出
- 点击"日志"按钮展开/收起
- 记录内容：VAD 事件、ASR 结果、状态变更、关键词命中、发送/接收
- 最多保留 80 条，自动滚动到最新
- 日志条目格式：`[时间] [状态] 消息内容`

## 完整流程示例

```
时间轴 ──────────────────────────────────────────────────→

[启动] ♪♪♪
  │
  ▼
wake_listening: VAD监听中...
  │  VAD检测到声 → 启ASR → "今天天气" → 没唤醒词 → 静默 → 丢弃
  │  VAD检测到声 → 启ASR → "开始" → 唤醒词命中!
  │
  ▼ ♪♪
listening: VAD+ASR持续运行，心跳♪...♪...♪(用户沉默时)
  │  用户说: "帮我查一下明天的天气说完了"
  │  → 关键词模块检测到"说完了" → 标记pending
  │  → VAD持续静默... 2秒到 → 确认发送!
  │
  ▼ ♪♪ 发送 (listening 不停，继续跑)
thinking: (异步) 文本→LLM→回复→TTS音频入队
  │
  │  同时 listening 继续: 用户又说 "还有后天的呢说完了"
  │
  ▼
播放控制:
  │  队列有音频，检查VAD → 用户还在说话? → 等
  │  用户静默了 → 开始播放 ♪
  │  播放中用户开口 → 暂停
  │  用户又静默 → 继续播放
  │  播完 → 检查队列下一个
  │
  ▼
listening 持续中... 心跳♪...♪...
  │  用户说: "结束结束"
  │
  ▼ ♪♪♪降调
wake_listening (回到待唤醒)
```

## 设计原则

| 原则 | 说明 |
|------|------|
| 输入永不停 | listening 状态下，不管 thinking 还是 playing，输入轨都在跑 |
| 播放看脸色 | 播放完全由 VAD 静默/说话控制，不抢话 |
| 模块独立 | VAD、ASR、关键词、播放、音效各自独立，可单独替换 |
| 发送双条件 | 关键词 + 静默2s 同时满足才发送 |
| 心跳提示 | 静默时低频轻音，让用户知道系统在听 |
| 异步不阻塞 | thinking 是异步的，不中断 listening |
